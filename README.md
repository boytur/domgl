# domgl

Render **HTML + GSAP scenes on the GPU** by sampling them once, then replaying them as
textures in WebGL and encoding with hardware H.264 (WebCodecs).

You keep authoring scenes in HTML/CSS/GSAP. `domgl` turns each scene into:

1. one transparent PNG per painted element (text, borders, SVG, shadows — all included), and
2. a per-frame transform track (`x`, `y`, `rotation`, `scale`, `opacity`) sampled from the
   real GSAP timeline.

Playback is then pure `three.js` + `VideoEncoder`, with no DOM and no per-frame screenshots.
On a 6-core laptop with an RTX 3050 it renders **1080×1920 at ~130 fps** — roughly 40–50×
faster than screenshotting every frame through a headless browser.

```
scene.html + GSAP ──transpile──▶ textures + frames.json ──render──▶ h264.mp4
```

## Install

```bash
npm install -g domgl
# or
npx domgl --help
```

Requires Node 20+, a Chrome/Chromium binary (set `CHROME_PATH` or let it auto-detect
Playwright / hyperframes caches), and a Chromium build with WebCodecs + hardware H.264.

## Quickstart

```bash
git clone https://github.com/boytur/domgl && cd domgl
npm install && npm run build

node dist/cli.js transpile examples/hello hello
node dist/cli.js lint examples/hello hello --strict
node dist/cli.js render examples/hello hello --out hello.mp4
```

`examples/hello/compositions/hello.html` is a complete 3-second scene — copy it and change
the markup. **You do not need any framework**: a scene is an HTML file with a paused GSAP
timeline registered on `window.__timelines`. See [docs/authoring.md](docs/authoring.md) for
the contract, what gets baked, and what to avoid.

If you already use HyperFrames, `compositions/<id>.html` is the same file — domgl reads that
folder directly, so nothing has to be rewritten.

## Usage

```bash
# 1. bake textures and sample motion
domgl transpile ./my-project s01 s02 s03

# 2. validate before rendering (recommended for generated scenes)
domgl lint ./my-project --strict

# 3. render
domgl render ./my-project s01 s02 s03 --out renders/out.mp4
```

### Project layout

```
my-project/
  compositions/      # one HTML file per scene, named <id>.html
    s01.html
    s02.html
  webgl/auto/        # generated by transpile
    s01.json
    s01/e0.png ...
```

`compositions/s01.html` is a plain document (no `<template>` wrapper) that contains the
markup, its styles, and a script that registers a paused GSAP timeline. If the scene needs a
helper (camera, snapping, …), pass `--stage path/to/helper.js`; it is injected before the
scene and runs first.

## Options

| flag | meaning |
|---|---|
| `--fps <n>` | sampling / encode rate, default `30` |
| `--max <n>` | max elements baked per scene, default `40` |
| `--out <file>` | output MP4 (render) |
| `--seconds <n>` | render only the first n seconds |
| `--bitrate <n>` | video bitrate, default `9000000` |
| `--compositions <dir>` | where scene HTML lives, default `compositions` |
| `--outdir <dir>` | where packages live, default `webgl/auto` |
| `--stage <file>` | helper script injected before the scene |
| `--strict` | lint: warnings become errors |
| `--json` | lint: machine-readable output |

## The package format

```jsonc
{
  "id": "s01",
  "fps": 30,
  "duration": 3.6,
  "width": 1080,
  "height": 1920,
  "elements": [
    {
      "i": 0, "tag": "div", "cls": "char",
      "x": 500, "y": 800, "w": 300, "h": 420,   // scene px, top-left origin
      "z": 6, "pad": 8,
      "tex": "s01/e0.png"
    }
  ],
  // frames[frameIndex][elementIndex] = [x, y, rotationRad, scale, opacity]
  "frames": [[[500, 800, 0, 1, 1], [0, 0, 0, 1, 1]]]
}
```

Rendered at `perspective: 1400px`-equivalent (`fov 30`), so elements keep their stacking
order and pixel placement.

## `domgl lint`

`lint` is the guard rail when a machine writes scenes. It checks:

- JSON parses, ids match, duration/fps sane
- every element has an existing texture, positive size, and a rect inside a sane range
- `frames.length === round(duration × fps)`
- every sample has 5 finite numbers, `0 ≤ opacity ≤ 1`, `0 < scale ≤ 12`
- warnings for static scenes, huge textures, blank textures, off-screen elements

Exit code is `1` when there are errors, so it drops straight into CI or an agent loop.

## Limitations

- **One texture per element** — heavy scenes (>60 moving parts) use a lot of VRAM. Use
  `--max` to cap, or merge static groups in the source.
- **Clip-path / masks / blend modes** are rasterised as they appear at sample time; if they
  change per frame, bake them into a single group instead.
- **Text is rasterised**, so it is fixed at the sampled resolution (1–3× source size).
- **Video elements** are not sampled; pass them as image sequences.
- Rotation is derived from the bounding box + matrix, so large rotations of non-square
  elements can drift slightly. Keep prop rotations under ~45°.
- Audio is not handled; mux it with ffmpeg (`-c:v copy`).
